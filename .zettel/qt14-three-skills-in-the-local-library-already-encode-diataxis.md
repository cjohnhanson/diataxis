Diátaxis is already load-bearing in the skill library on this machine, at ~/Projects/co.d/skills.

doc-editing enforces one document, one type, and names the leaks it watches for: reference material inside a tutorial, reference material inside an explanation. Its phase-one gate refuses to draft until type, audience, and purpose are settled.

writing-docs-eval evaluates a document in three frameworks: IBM DQTI for the nine quality characteristics, Diátaxis for per-type criteria, and Baker's Every Page is Page One for topic independence. Its procedure classifies the document first, then tests it against the criteria for that type, and it says that a document serving two types should be split.

writing-review dispatches the other two.

Nothing in the library covers the workflow described in [[oxz9]], the incremental loop.
