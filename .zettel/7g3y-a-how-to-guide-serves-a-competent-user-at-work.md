A how-to guide is goal-oriented. It directs a user who already holds the skill and already knows the result they want. It carries action and only action: no teaching, no explanation, no reference tables, no digression.

Real problems fork, so a guide forks with them. It uses conditional imperatives, "if you want x, do y", and it expects the reader to apply judgement. Practical usability beats completeness.

The title states the goal. "How to integrate application performance monitoring" is right. "Integrating application performance monitoring" is weaker, and the bare noun phrase is worse, because neither says whether the page instructs.
